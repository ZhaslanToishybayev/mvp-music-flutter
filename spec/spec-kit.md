# Spec‑Kit

Source of truth for WHAT to build.

## Structure
- spec/specs/ — approved specs for features/fixes.
- spec/templates/ — templates to author new specs.

## Workflow
1) Pick a template from spec/templates/.
2) Create spec/specs/YYYY-MM-DD-topic.md.
3) Keep it concise, with measurable Acceptance Criteria (Given/When/Then).
4) Link the spec in PR; keep it updated if scope changes.

## Naming
- YYYY-MM-DD-topic.md or eature-name.md.
- Prefer checklists and short examples.
